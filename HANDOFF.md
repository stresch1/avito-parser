# AvitoParser — заметки для продолжения работы

Документ для Claude в новой сессии: что это за проект, как он устроен сейчас,
что сделано и почему, что известно о проблемах. Читать перед тем, как
что-то менять — большая часть решений здесь уже была осознанным выбором,
а не случайностью.

## Что это

Приложение (FastAPI + Playwright) для сбора объявлений с Avito
(грузовики/спецтехника, экскаваторы и т.п.) в Excel. Владелец — маркетолог
(Юрий), делает инструмент для коллеги (Даша), нужен парсинг больших объёмов
(тысячи объявлений) для аналитики.

Есть **два способа запуска одного и того же кода**:
1. Веб-версия — `uvicorn app.main:app`, открывается в браузере на
   `http://127.0.0.1:8000`
2. Десктоп-версия — `desktop.py` (или собранный `dist/AvitoParser.exe`),
   тот же FastAPI-бэкенд и тот же `app/static/` интерфейс, просто в нативном
   окне через `pywebview` вместо вкладки браузера

Расположение на этом компьютере: `C:\Users\Admin\Desktop\claude code\AvitoParser`
(перенесено с другого ПК в текущей сессии — в старой версии `HANDOFF.md`
были пути `C:\Users\Даша\Desktop\AvitoParser`, они больше не актуальны).

## Архитектура сейчас

- `app/main.py` — FastAPI: API-эндпоинты, задачи в SQLite, валидация ссылок
- `app/scraper.py` — вся логика парсинга на Playwright (единственный способ
  сбора данных — экспериментальный HTTP-режим без браузера пробовали и
  **откатили**, см. хронологию)
- `app/paths.py` — единая точка для путей: `data_dir()` (пользовательские
  данные — БД, ключи, прокси, экспорт) и `resource_path()` (упакованные
  ресурсы вроде `static/`). Работает одинаково что из исходников, что из
  собранного PyInstaller `.exe` — **этим модулем нужно пользоваться для
  любых новых путей к файлам**, не писать `Path(__file__)...` напрямую
- `app/proxies.py` — загрузка прокси из `data/proxies.txt`
- `app/socks_relay.py` — локальный SOCKS5-релей без внешних зависимостей
  (Chromium не умеет авторизовываться на SOCKS5 с логином/паролем — этот
  модуль поднимает на 127.0.0.1 прокси без авторизации, который сам логинится
  в апстрим)
- `app/captcha_solver.py` — автоматическое решение капчи через 2captcha
- `app/cookie_service.py` — интеграция с spfa.ru (готовые "прогретые" cookies
  вместо решения капчи постфактум — см. раздел про spfa.ru ниже)
- `app/db.py` — SQLite-хранилище задач
- `app/exporter.py` — выгрузка в xlsx
- `app/columns.py` — список колонок и маппинг параметров объявления
- `app/static/` — фронтенд (index.html, app.js, style.css, app_icon.ico)
- `desktop.py` — точка входа десктоп-версии (поднимает uvicorn в фоновом
  потоке + окно pywebview + нативный API для сохранения файлов)
- `desktop.spec` — конфиг сборки PyInstaller (`pyinstaller desktop.spec`)
- `data/proxies.txt` — список прокси (обычно пусто, парсер идёт с домашнего IP)
- `data/captcha_key.txt`, `data/spfa_key.txt` — ключи API (уже вставлены)
- `data/progress.log` — **полный лог всех прогонов** (в БД хранится только
  последнее сообщение прогресса на задачу, для истории — только этот файл)
- `data/db/tasks.sqlite3` — история задач

## Как запустить

Веб-версия из исходников:
```
cd "C:\Users\Admin\Desktop\claude code\AvitoParser"
venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```
Открыть http://127.0.0.1:8000.

Десктоп-версия из исходников: `venv\Scripts\python.exe desktop.py`

Пересборка `.exe`: `venv\Scripts\python.exe -m PyInstaller desktop.spec --noconfirm`
— результат в `dist/AvitoParser.exe`. **Перед пересборкой закрыть уже
запущенный `.exe`**, иначе файл занят и PyInstaller не сможет его перезаписать.

## Хронология (что чинили и почему, в порядке появления)

### Первая сессия (другой компьютер, до переноса)

1. Playwright не мог скачать Chromium (сеть блокировала cdn.playwright.dev)
   → `channel="chrome"`, использует системный Chrome.
2. Прокси — датацентровые Avito банит мгновенно, нужен резидентный/мобильный.
   Chromium не умеет SOCKS5-авторизацию → написан `socks_relay.py`.
3. Базовая защита от блокировки Avito (`_goto_with_retry`): статус 403/429,
   автоперезагрузка, 2captcha, ручное решение в видимом окне (`headless=False`).
4. Гибридный сбор: карточки с выдачи + заход в каждое объявление за полными
   данными, с fallback на данные карточки при неудаче захода.
5. Один `page.evaluate()` вместо ~15 запросов на объявление; `ITEM_CONCURRENCY=4`
   параллельных вкладок.
6. Пагинация выдачи: убрали привязку к устаревшему селектору кнопки
   "следующая страница", идём по факту наличия карточек.
7. Точечно починены Город/Адрес/Просмотры сегодня/Тип продавца/Компания/
   Ссылка на продавца/XL/Выделено/Продвижение.
8. 2captcha для Яндекс SmartCaptcha (пазл-слайдер) — CapMonster **не подходит**,
   такой капчи у них нет.
9. Таймаут на `scrape_item()` целиком (`ITEM_TIMEOUT=360`) — `page.evaluate()`/
   `page.reload()` без таймаута реально зависали на часы.
10. Периодическая пауза `BATCH_PAUSE_EVERY=100` / `BATCH_PAUSE_SECONDS=25`.
11. `context.close()`/`browser.close()` в try/except — не терять уже собранные
    строки при падении браузера.

### Текущая сессия (перенос на новый ПК + большая доработка)

12. **Перенос проекта** на этот компьютер, venv пересоздан (доступен только
    Python 3.14, а не 3.12 — проблем не возникло).
13. **Разбиение выдачи по цене**: Avito обрубает глубину пагинации на одной
    непрерывной выдаче (~1400-1500 карточек), даже если объявлений реально
    больше. Раньше это выглядело как "конец списка" (пустая/короткая
    последняя страница) — неотличимо от настоящего конца каталога. Решение:
    сверяться с реальным счётчиком Avito в шапке (`data-marker="page-title/
    count"`), и если собрано заметно меньше — делить диапазон цены (`pmin`/
    `pmax`) пополам и дособирать половины рекурсивно (`MAX_PRICE_SPLIT_DEPTH=6`).
    Дочерние диапазоны собираются **параллельно** (`LISTING_RANGE_CONCURRENCY=3`)
    — иначе на сильно неровном распределении цен разбиение растягивается
    надолго. Проверено вживую: собрало 1839 из 1839 без разрыва.
14. **Валидация ссылок при создании задачи** ужесточена (`urlparse`, домен
    должен реально быть `avito.ru`) — раньше склеенная в поле ввода ссылка
    (`https:https://...`) проходила проверку и падала только через минуту
    работы браузера с непонятной ошибкой.
15. **Интеграция spfa.ru** (`app/cookie_service.py`) — платный сервис
    "прогретых" cookies для Avito (документация: `spfa.ru/api/docs/`).
    В начале каждой ссылки запрашиваются стартовые cookies+user-agent; при
    блокировке — сначала пробуем разблокировать текущие cookies через spfa,
    потом взять новые, и только если не помогло — откат на 2captcha/ручное
    решение. Ключ уже сохранён. **Сервис бывает нестабилен** (503) — это
    не баг интеграции, у них так и написано на сайте.
16. **Десктоп-версия приложения** — `desktop.py` + `desktop.spec`, тот же
    бэкенд и интерфейс в окне `pywebview`, собирается в один `.exe` через
    PyInstaller. Playwright продолжает ходить через системный Chrome — сам
    браузер паковать не нужно, только driver-бинарник Playwright (есть
    официальный PyInstaller-хук, подхватывается сам).
    - Скачивание файлов в окне `.exe` **не работает как обычная ссылка**
      (WebView2 — не полноценный браузер, нет менеджера загрузок) — решено
      через нативный диалог `create_file_dialog` в `desktop.py` (класс `Api`,
      `window.pywebview.api.save_file`), в `app.js` — ветка `if
      (window.pywebview)`. В браузерной версии ничего не поменялось.
    - Пути к данным: `app/paths.py` — `data_dir()` рядом с `.exe`,
      `resource_path()` для упакованной статики (учитывает `sys._MEIPASS`).
    - Старые задачи с абсолютными путями к экспортированным файлам (с ДРУГОГО
      компьютера, до переноса) — раньше скачивание падало ("файл не найден").
      Теперь в БД хранится только имя файла, путь всегда собирается заново
      из текущей `EXPORTS_DIR` — работает и для старых записей (берёт из них
      только basename), и переживает перенос программы в другое место.
    - Иконка `.exe`/окна — `app/static/app_icon.ico` (логотип "Parser for
      ADK" с миньоном, присланный пользователем).
17. **Экспериментальный HTTP-режим без браузера** (`curl_cffi` + разбор
    embedded JSON, подсмотрено в github.com/Duff89/parser_avito) — был
    реализован как опциональный быстрый путь с автоматическим откатом на
    Playwright при неудаче. **Полностью убран по просьбе пользователя** —
    решили оптимизировать проверенный Playwright-путь вместо параллельной
    архитектуры. Если тема всплывёт снова — в истории сессии есть рабочая
    реализация с разбором embedded JSON страницы выдачи и AJAX-эндпоинта
    `/web/1/js/items`, можно поднять как отправную точку.
18. **Оптимизация Playwright-пути** (взамен HTTP-режима):
    - блокировка загрузки картинок/шрифтов/видео через `context.route()` —
      данные всё равно читаются из DOM/атрибутов, а не из самих файлов;
      перед ручным решением капчи блокировка временно снимается и страница
      перезагружается, чтобы графика капчи (пазл-слайдер) отрисовалась
    - пул вкладок (`asyncio.Queue`) вместо открытия/закрытия новой вкладки
      на каждое объявление — `scrape_item()` теперь принимает готовую `page`,
      а не `context`
    - проверено вживую на реальных объявлениях: обработка одного объявления
      ~2.7 сек, 112 запросов картинок подтверждённо оборваны, данные
      извлекаются корректно
19. **Баланс spfa.ru в интерфейсе** обновлялся только при открытии
    приложения — добавлено периодическое обновление раз в минуту
    (`setInterval(loadCookieServiceKey, 60000)` в `app.js`).

## Известные ограничения / не до конца решено

- **`limit_per_link` не обрывает сбор списка объявлений досрочно** —
  `collect_listing_cards`/`_collect_listing_cards_single` всегда листают
  страницу до конца (или до лимита пагинации Avito), лимит применяется уже
  к собранному списку. На маленьких категориях не заметно, но если задать
  небольшой лимит на категории с тысячами объявлений — сбор списка всё
  равно займёт время, соразмерное полному размеру категории. Не почищено —
  не было явного запроса, но стоит иметь в виду при следующей оптимизации.
- **spfa.ru периодически нестабилен** (503 "Сервис временно недоступен") —
  это ограничение самого сервиса, не баг. Откат на 2captcha/ручное решение
  срабатывает автоматически.
- **2captcha не всегда решает капчу** — ограничение сервиса распознавания
  для Яндекс SmartCaptcha, не баг кода. `CAPTCHA_SOLVE_ATTEMPTS=3`.
- **Селекторы для XL/Выделено/Продвижение на карточках выдачи — best-effort**,
  искались по словам в тексте карточки ("XL", "Выделено", "Продвинуто/
  Поднято/TOP/Premium/VIP"). Если колонки пустые/неточные — смотреть реальный
  HTML карточки и поправить `_extract_search_page_cards()`.
- **`headless=False` намеренно** — нужно видимое окно для ручного решения
  капчи. Заголовок вкладки меняется на "⏳ НЕ ЗАКРЫВАЙТЕ" / "🖐 РЕШИТЕ КАПЧУ
  ВРУЧНУЮ", чтобы это было видно даже в свёрнутом виде/таскбаре.
- **Мобильный/резидентный прокси не куплен** — обсуждали, решили не покупать
  из-за цены (~2500₽/мес), полагаемся на связку spfa.ru + редкую ручную
  капчу. Один купленный дешёвый серверный SOCKS5-прокси оказался уже
  забанен Avito сам по себе (проверено напрямую curl'ом, без браузера) —
  такие прокси для Avito бесполезны без cookie-сервиса поверх них.

## Полезные константы (в начале `app/scraper.py`)

```python
NAV_TIMEOUT = 30000                # таймаут навигации, мс
ITEM_CONCURRENCY = 4               # параллельных вкладок на объявления (=размер пула)
CAPTCHA_SOLVE_ATTEMPTS = 3         # попыток автоматически решить капчу
ITEM_TIMEOUT = 360                 # потолок на обработку одного объявления, сек
BATCH_PAUSE_EVERY = 100            # пауза после стольких объявлений
BATCH_PAUSE_SECONDS = 25           # длительность паузы, сек
MAX_SEARCH_PAGES = 500             # предохранитель от бесконечной пагинации
MAX_PRICE_SPLIT_DEPTH = 6          # макс. уровней разбиения выдачи по цене
LISTING_RANGE_CONCURRENCY = 3      # параллельных диапазонов цены при разбиении
COUNT_TOLERANCE_ABS = 5            # допустимый недобор против счётчика Avito, шт
COUNT_TOLERANCE_REL = 0.01         # то же, в долях от счётчика
```

## Как диагностировать проблему в новой сессии

1. Прочитать `data/progress.log` (полная история, не только последнее
   сообщение) — там видно, на каком именно шаге что пошло не так, включая
   сообщения от spfa.ru/2captcha/разбиения по цене.
2. Проверить статус задач: `GET http://127.0.0.1:8000/api/tasks`
   (или порт десктоп-версии — печатается не в лог, а слушается на случайном
   свободном порту; найти можно через `Get-NetTCPConnection -OwningProcess
   <pid>` в PowerShell по PID процесса `AvitoParser.exe`/`python.exe`).
3. Если сервер долго не отвечает / завис — вероятно, снова где-то
   бесконечный `await` без таймаута в новом месте кода.
4. Если "скачивание не работает" — уточнить, в браузере это или в `.exe`
   (разные механизмы, см. п.16 хронологии).
5. Если "долго парсит" на чужом компьютере (ноутбук) — в первую очередь
   проверить, не уходит ли устройство в сон (не просто гаснет экран) при
   бездействии: Windows на ноутбуках агрессивнее десктопов по умолчанию.
